UI가 게임 상태를 보여 주기만 하고 바꾸기는 요청으로 하며, 번역 · 입력 장치 · 접근성 · 해상도에서 깨지지 않게 하는 규칙이다.

## 언제 붙이나
- UI 프로그래머가 화면 · HUD · 메뉴 · 대화 상자 코드를 쓰거나 고치는 일.
- UX 디자이너의 화면 명세를 구현하는 일, 그 결과를 접근성 전문가 · 현지화 리드가 볼 때.
- 붙이지 않는 때: UI 그림 자원만 바뀌는 일, UI에 닿지 않는 게임플레이 일.

## 기준
- **표시만 한다.** UI는 게임 상태를 갖거나 바로 고치지 않는다. 보여 주기만 하고, 바꾸려면 명령 · 이벤트로 요청한다. 상태 변경 요청과 표시를 가른다.
- **번역.** 플레이어가 보는 글은 모두 현지화 시스템을 거친다. 코드에 박은 문구를 두지 않는다.
- **입력 장치.** 상호작용 요소는 대상 플랫폼의 입력 장치 모두로 쓸 수 있다. 원문은 모든 요소에 키보드 · 마우스와 게임패드 둘 다를 요구했다 — 대상 플랫폼이 정한 장치로 바꿔 읽는다. 어느 장치가 대상인지 적는다.
- **애니메이션.** 애니메이션은 건너뛸 수 있고, 사용자의 움직임 줄이기 · 접근성 설정을 따른다.
- **소리.** UI 소리는 오디오 이벤트 시스템으로 낸다. 바로 재생하지 않는다.
- **게임 스레드.** UI는 게임 스레드를 막지 않는다.
- **접근성 목표.** 접근성 요구 문서(`templates/accessibility-requirements`)의 목표 단계가 요구하는 기능을 넣는다(문서가 없으면 그 사실을 보고에 적는다).
- **해상도.** 모든 화면을 지원하는 가장 작은 해상도와 가장 큰 해상도에서 시험한다.
- 엔진별 쓰는 법(UI 틀 · 초점 이동 · 번역 함수)은 프로젝트의 엔진 참조 문서와 그 엔진 전문가 역할이 정한다.

## 확인하는 법
검사로 만들 수 있는 것:
- 박은 문구 — lint. UI 코드에서 번역 함수 밖의 문자열 리터럴을 찾는다(로그 · 키 이름은 허용 목록). 코드가 쓰는 키가 번역 표에 모두 있는지, 언어마다 빠진 키가 없는지 대조하는 스크립트.
- 표시만 — 정적 검사. UI 폴더 코드가 게임 상태를 쓰는 길(상태 객체의 설정 함수 · 가변 필드)을 부르는지 찾는다. 허용하는 길은 명령 · 이벤트 목록뿐이다.
- 소리 — 정적 검사. UI 코드가 소리 재생 API를 바로 부르면 실패.
- 입력 장치 — UI 자동 시험. 마우스 없이 초점을 옮겨 화면의 상호작용 요소마다 닿고 누를 수 있는지. 대상 장치마다 돌리고, 닿은 요소 수와 전체 수를 찍는다.
- 애니메이션 — 시험. 움직임 줄이기 설정을 켜고 화면을 열어 애니메이션이 꺼지거나 줄었는지, 건너뛰기 입력으로 끝나는지.
- 해상도 — 시험. 가장 작은 · 가장 큰 해상도에서 화면을 캡처하고, 요소가 화면 밖으로 나가거나 글이 잘린 곳을 자동으로 찾는다. 일부러 길게 늘린 가짜 번역문을 넣어 같이 돌리면 번역 길이 문제도 잡는다.
- 게임 스레드 — 성능 시험. 화면 열기 · 긴 목록 갱신 때 프레임 시간이 상한을 넘으면 실패.
- 접근성 목표 — 시험. 접근성 요구 문서의 목표 단계가 요구하는 기능이 있고, 켜면 화면이 깨지지 않는지 본다(글자 크기 · 색각 모드가 대상이면 위 해상도 검사와 같이 돌린다). 문서가 없어 목표 단계를 모르면 「못 봄 — 목표 단계 입력 없음」으로 적는다.

사람이나 검토 역할이 볼 것:
- 색각 모드에서 실제로 구별되는가, 글자가 읽히는가 — 접근성 전문가.
- 번역문의 뜻이 맞고 자리가 넉넉한가 — 현지화 리드.
- 화면이 보기 좋고 쓰기 쉬운가 — UX 디자이너와 사람. 캡처가 있다는 것은 조작감의 증거가 아니다.

판정: 기준마다 통과 · 실패 · 못 봄 · 해당 없음과 근거(파일:줄 · 캡처 · 시험 이름)를 적는다. 대상 장치 가운데 시험하지 못한 장치가 있으면 입력 기준은 그 장치에 대해 「못 봄」이다. 애니메이션이 없는 화면의 애니메이션 기준은 「해당 없음」이다.
