구현한 코드가 일의 수용 기준 · 구조 결정 기록(ADR) · 코딩 기준을 따르는지, 그리고 구조 문서를 정한 엔진과 언어로 실제로 구현할 수 있는지를 처음 보는 검토 세션이 묻게 하는 질문 모음이다. 원문의 구현 검토 둘이 소제목 둘이다.

## 언제 붙이나
- 검토 역할은 총괄이 그때 고른 검토 세션이다(코드나 구조를 쓴 세션이 아니다). 리드 프로그래머 역할 글을 줄 수 있으나 직함이나 위아래가 아니라 처음 보는 눈이 요점이다. 검토 역할은 읽고 판정과 근거를 보고하며 파일을 고치지 않는다. 정하는 것은 총괄이다.
- 총괄은 지금 산출물에 맞는 소제목만 골라 그 「볼 자료」와 같이 준다. 질문 글은 검토 세션이 읽는다. 동작이 바뀌지 않는 작은 고침(낱말 · 주석)에는 붙이지 않는다.
- 쓰는 때(단계 이름과 수는 프로젝트가 정한다 — 예: 구상 → 시스템 기획 → 기술 준비 → 제작 → 마감 → 출시):
  - 구현 검토: 제작에서 게임플레이 프로그래머 · 엔진 프로그래머 · UI 프로그래머 등이 일(스토리) 하나를 구현했을 때마다, 끝났다고 부르기 전.
  - 구현 가능성: 기술 준비에서 구조 문서를 쓴 뒤, 그리고 새 구조 패턴을 낼 때 엔진 · 언어별 구현 제약과 인터페이스 정의를 본다. 기술 요구 덮음과 시스템 경계는 `rules/review-technical`에서 본다.
- 의뢰에 줄 것 · 지적의 꼴 · 기술 빚 기록은 코드 검토 절차(`procedures/code-review`)를 따른다. 총괄이 이 규칙과 함께 꺼내 맡기는 글에 경로를 적는다. 이 글은 물을 것만 정한다.
- 판정은 「판정과 증거의 규칙」(`rules/verdicts`)을 따른다. 볼 자료를 못 읽은 질문은 못 봄이다.

## 기준
### 구현이 수용 기준과 결정 기록을 따르는가
- 볼 자료: 구현 파일 경로 · 일 파일(수용 기준) · 관련 기획 문서 절 · 이 시스템을 다스리는 결정 기록.
- 물을 것:
  - 일의 수용 기준과 다스리는 결정 기록에 맞게 구현됐는가.
  - 코드가 구조의 경계 정의와 맞는가.
  - 코딩 기준 위반이나 금지 패턴이 있는가.
  - 공개 API가 시험할 수 있고 설명이 붙어 있는가.
  - 기획 문서의 규칙에 비춰 틀린 동작이 있는가.
- 실패로 보는 것: 합치기 전에 고쳐야 하는 문제. 그 밖의 구체적인 문제는 우려로 남긴다.
- 못 봄으로 남기는 것: 구현 파일이나 수용 기준을 읽지 못했다. 다스리는 결정 기록이 있다는데 읽지 못했으면 못 봄이고, 그런 결정 기록이 없으면 「없음」으로 적는다(그 질문은 해당 없음).

### 구조를 그 엔진과 언어로 구현할 수 있는가
- 볼 자료: 구조 문서 · 기술 요구 기준선 요약 · 결정 기록 목록과 상태.
- 물을 것:
  - 정한 엔진 · 언어로 구현하기 어렵거나 안 되는 결정이 있는가.
  - 프로그래머가 스스로 지어내야 할 만큼 빠진 인터페이스 정의가 있는가.
  - 피할 수 있는 기술 빚을 낳거나, 그 엔진의 흔한 쓰는 법과 어긋나는 패턴이 있는가.
- 실패로 보는 것: 적힌 대로는 구현할 수 없게 만드는 막힘. 짚은 항목들은 우려로 남긴다.
- 못 봄으로 남기는 것: 구조 문서나 결정 기록 목록을 읽지 못했다. 엔진의 쓰는 법을 프로젝트의 엔진 참조로 확인하지 못한 주장은 「출처 없음」으로 적는다. 엔진별 쓰는 법은 프로젝트의 엔진 참조 문서와 그 엔진 전문가 역할이 정한다.

## 확인하는 법
검사로 만들 수 있는 것: 시험과 빌드(지휘자가 검사 명령으로 돌린다 — 시험 0개는 통과가 아니다) · lint와 정적 분석으로 코딩 기준 · 금지 패턴 · 공개 API 설명 주석 · 층 경계를 넘는 참조(가져오기 규칙)를 잡는다. 수용 기준을 채우는지 · 기획 규칙과 맞는지 · 구조가 구현할 만한지는 검토 역할이 본다.
검토 역할이 볼 것: 파일을 끝까지 읽고 질문에 하나씩 답한다. 지적마다 파일:줄과 인용을 붙인다. API 이름 · 엔진 판에 묶인 주장은 엔진 참조의 줄을 댄다.
판정 적기: 소제목마다 통과 · 실패 · 못 봄 · 해당 없음 하나와 근거 · 우려 목록(무엇 · 어디 · 누구 몫) · 못 봄이면 빠진 자료. 소제목을 둘 다 썼으면 엄한 쪽이 전체 판정이다. 실패의 고침은 총괄이 구현 역할에게 돌려보낸다.
