게임 규칙을 구현한 코드가 기획이 바꿀 값을 코드 밖에 두고, 상태마다 주인이 분명하며, 프레임 속도에 흔들리지 않고, 표시와 갈라 시험할 수 있게 하는 규칙이다.

## 언제 붙이나
- 게임플레이 프로그래머가 전투 · 이동 · 자원 · 진행 같은 게임 규칙을 구현하거나 고치는 일.
- 기획 문서(조절값 목록이 있는 것)를 코드로 옮기는 일.
- 붙이지 않는 때: 버릴 시제품(`rules/prototype-code` 규칙이 이 기준을 느슨하게 한다), 엔진 핵심 코드(`rules/engine-code`), UI 코드만 바뀌는 일(`rules/ui-code`).

## 기준
- **조절 대상을 정한다.** 기획이 바꿀 값(원문의 예: 기본 피해 · 이동 속도)은 자료 · 설정 파일에서 읽는다. 무엇이 조절 대상인지는 기획 문서의 조절값 목록이 정한다. 목록이 없으면 구현 역할이 고른 목록을 보고에 적는다. 원문은 모든 게임플레이 값을 밖으로 빼라고 했다 — 조절 대상이 아닌 값은 이름 있는 상수로 두어도 되고, 코드에 박은 조절 대상은 이유를 적는다.
- **시간 단위를 정한다.** 시간에 따르는 계산은 경과 시간(델타 시간)으로 한다. 프레임 속도가 달라도 결과가 같게 하려고. 시간 값의 단위(초 · 프레임 · 틱)를 이름이나 주석에 적는다. 원문의 틀린 예: 속도를 코드에 박고 델타 시간도 곱하지 않은 것.
- **상태의 주인을 정한다.** 게임 상태마다 주인 하나를 정해 적고, 다른 시스템은 주인에게서 받아(주입) 쓴다. 게임 상태를 정적 단일 객체(싱글턴)에 두지 않는다 — 원문은 전면 금지였다. 엔진의 전역 객체를 써야 하면 무엇을 들고 누가 주인인지와 이유를 적는다.
- **UI와 가른다.** 게임플레이 코드는 UI 코드를 바로 참조하지 않는다. 시스템 사이의 소통은 이벤트(엔진의 신호 · 이벤트 · 대리자)로 한다.
- **인터페이스.** 게임플레이 시스템마다 분명한 인터페이스를 내놓는다.
- **상태 기계.** 상태 기계에는 명시적인 전이 표가 있고, 상태마다 설명이 있다.
- **시험.** 규칙 논리를 표시에서 갈라 단위 시험을 쓴다. 원문은 모든 게임플레이 논리에 요구했다 — 보통은 그렇게 하고, 자동 시험으로 볼 수 없는 것(느낌 · 화면)은 이유와 손으로 확인할 단계를 적는다(`rules/test-standards` 규칙).
- **기획 연결.** 기능마다 어느 기획 문서를 구현했는지 코드 주석에 적는다.
- 엔진별 쓰는 법(설정을 읽는 길 · 이벤트 꼴 · 시간 값)은 프로젝트의 엔진 참조 문서와 그 엔진 전문가 역할이 정한다.

## 확인하는 법
검사로 만들 수 있는 것:
- 박힌 숫자 — 정적 검사. 게임플레이 코드에서 숫자 리터럴을 찾는다(0 · 1 · -1, 이름 있는 상수의 정의, 이유 적힌 예외 목록은 뺀다). 결과는 후보다. 더 강한 검사: 기획 문서 조절값 표의 이름이 자료 파일 키에 모두 있고 코드가 그 키를 읽는지 대조하는 스크립트.
- 시간 단위 — 시험. 같은 상황을 서로 다른 프레임 간격 두 가지 이상으로 흉내 내, 같은 경과 시간 뒤 위치 · 타이머 값이 허용 오차 안에서 같은지. 갱신 함수의 이동 계산에 델타가 없는 곳을 찾는 정적 검사는 후보만 낸다.
- UI와 가르기 — 정적 검사. 게임플레이 폴더의 가져오기가 UI 폴더 · 모듈을 가리키면 실패.
- 상태의 주인 — 정적 검사. 정적 가변 필드 · 싱글턴 꼴을 찾아 이유 적힌 허용 목록과 대 본다.
- 상태 기계 — 시험. 전이 표에 없는 전이를 시도하면 막히는지. 스크립트로 표의 상태마다 설명이 있는지.
- 시험 — 규칙 논리 파일마다 맞는 시험이 있고, 시험 명령에서 실제로 돈 시험 수가 0보다 큰지. 0개 돌고 0으로 끝난 것은 통과가 아니다.
- 기획 연결 — 스크립트. 기능 주석이 가리킨 기획 문서가 실제로 있는지.

사람이나 검토 역할이 볼 것:
- 무엇을 조절 대상으로 볼지 — 시스템 디자이너가 조절값 목록으로 정한다. 값 자체는 게임 내용이라 사람이 정한다(총괄을 거쳐).
- 인터페이스가 분명한가, 상태마다 주인이 하나인가 — 쓴 역할이 아닌 리드 프로그래머가 검토한다.
- 손맛 · 조작감 — 사람이 해 본다. 시험 통과는 손맛의 증거가 아니다.

판정: 기준마다 통과 · 실패 · 못 봄 · 해당 없음과 근거(파일:줄 · 시험 이름 · 검사 출력)를 적는다. 시간에 따르는 계산이 없는 일의 시간 단위 기준은 「해당 없음」이다. 상태 기계가 없으면 그 기준도 「해당 없음」이다.
