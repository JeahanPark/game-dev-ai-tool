여러 기기가 한 게임을 나눌 때 누가 진짜 상태를 정하는지, 판이 달라도 말이 통하는지, 끊기고 늦어도 버티는지, 나쁜 패킷을 막는지를 지키게 하는 규칙이다. 기준 몇은 그 게임의 네트워크 방식에 따라 붙이거나 뺀다.

## 언제 붙이나
- 네트워크 프로그래머가 접속 · 메시지 · 복제 · 예측 코드를 쓰거나 고치는 일.
- 게임플레이 프로그래머의 일이 네트워크로 나누는 상태를 더하거나 바꿀 때.
- 보안 엔지니어가 받은 패킷 검증과 권위 경계를 볼 때.
- 붙이지 않는 때: 혼자 하는 게임, 네트워크로 나누는 상태를 건드리지 않는 일.

## 기준
- **권위.** 게임에 중요한 상태는 권위를 가진 쪽(원문은 서버)이 정한다. 클라이언트가 보낸 값을 그대로 믿지 않는다. 이 게임에서 권위가 어디인지 적는다.
- **메시지 버전.** 네트워크 메시지에는 버전을 붙여 앞뒤 판이 서로 읽을 수 있게 한다.
- **예측과 맞춤.** 클라이언트는 자기 쪽에서 미리 움직이고(예측) 서버 결과와 맞춘다. 예측이 틀리면 되감아 다시 맞춘다(롤백). 원문은 모든 게임에 되감기를 요구했다 — 예측이 필요한 방식에만 붙이고, 필요 없는 방식이면 「해당 없음」과 이유를 적는다.
- **끊김.** 끊김 · 다시 접속을 매끄럽게 다룬다. 호스트 이전은 호스트가 있는 방식에서만 붙인다(원문은 셋 다 요구했다).
- **로그 빈도.** 네트워크 로그에는 빈도 제한을 둔다. 로그가 넘쳐 다른 기록을 덮지 않게.
- **복제 방식.** 네트워크로 나누는 값마다 복제 방식을 적는다: 믿을 수 있는 전송인가 아닌가(reliable · unreliable), 빈도, 보간.
- **대역폭.** 메시지 종류별 대역폭 예산을 정하고 쓰는 양을 잰다.
- **받은 패킷 검증.** 들어온 패킷의 크기와 칸마다의 범위를 검증한다.
- 엔진별 쓰는 법(복제 표시 · 원격 호출 꼴 · 네트워크 부품)은 프로젝트의 엔진 참조 문서와 그 엔진 전문가 역할이 정한다.

## 확인하는 법
검사로 만들 수 있는 것:
- 받은 패킷 검증 — 시험(경계 값 · 무작위 입력). 너무 큰 패킷 · 잘린 패킷 · 범위 밖 칸을 보내 거부되고 서버가 멈추지 않는지. 보낸 사례 수를 찍는다.
- 권위 — 시험. 클라이언트 쪽에서 바꾼 값(있을 수 없는 체력 · 재화 같은 것)을 보내 권위 쪽 상태가 그대로인지.
- 메시지 버전 — lint로 메시지 정의마다 버전 칸이 있는지. 호환 시험: 저장해 둔 이전 판 메시지 견본을 새 코드로 읽고, 새 메시지를 이전 판의 읽기 코드로 읽어 본다.
- 복제 방식 — 스크립트. 나누는 값 목록과 복제 방식 표를 대조해 칸이 빈 값을 낸다.
- 대역폭 — 시험. 정한 장면을 정한 시간만큼 돌려 메시지 종류별 바이트를 재고, 예산을 넘으면 실패.
- 로그 빈도 — 시험. 같은 오류를 많이 일으켜 로그 줄 수가 상한 아래인지.
- 끊김 — 시험. 연결을 끊고 다시 붙여 상태가 이어지는지. 지연 · 손실을 흉내 내는 도구가 있으면 그 위에서 돌린다.
- 예측과 맞춤 — 시험. 지연을 흉내 내 예측이 틀리게 한 뒤, 클라이언트 상태가 권위 쪽 상태로 돌아오는지.

사람이나 검토 역할이 볼 것:
- 지연 · 손실이 있을 때의 조작감 — 혼자 돌린 판은 보여 주지 못한다. 사람이 실제 상대나 흉내 낸 지연으로 해 본다.
- 권위 경계에 빠진 곳이 없나(어느 상태가 게임에 중요한가) — 보안 엔지니어 · 리드 프로그래머가 검토한다.

판정: 기준마다 통과 · 실패 · 못 봄 · 해당 없음과 근거(시험 이름 · 잰 값 · 파일:줄)를 적는다. 대역폭 예산을 정하지 않았으면 「실패 — 요구한 예산 없음」이다. 예산 문서를 검토하는 쪽이 받지 못했으면 「못 봄 — 예산 입력 미수신」이다(`rules/verdicts`). 예측을 쓰지 않는 방식의 되감기 기준은 「해당 없음 — 이유」다.
