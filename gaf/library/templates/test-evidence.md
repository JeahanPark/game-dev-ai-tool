>
> 「시험 파일이 있다」는 「시험이 통과했다」가 아니다 — 두 칸을 따로 적는다. 이름만 적고 파일이 없는 그림은 증거가 아니다. 증거를 얻은 뒤 관련 코드가 바뀌었으면 그 기준의 결과를 「못 봄 — 증거를 얻은 뒤 변경됨」으로 돌린다. 채운 문서에서는 이 칸을 지운다.

|---|---|---|---|---|---|---|---|---|

| 2 | <기준 문구> | | | | | | | |
| 3 | <기준 문구> | | | | | | | |

- 결과 낱말은 넷뿐이다. 못 봄(확인을 못 함 · 증거를 못 읽음 · 시험이 0건 돎)은 통과가 아니다. 못 봄이면 메모에 무엇이 없었는지 적는다.
- 해당 없음은 그 기준이 이번 빌드에 걸리지 않을 때만 쓰고, 까닭을 메모에 적는다.
- 「사람이 해 봄」은 사람이 실제로 하고 답한 것만 적는다. 그 답을 대신 채우지 않는다.
- 「다시 볼 것」이 「예」이면 결과를 못 봄으로 바꾼다. 다시 확인하기 전에는 통과로 세지 않는다.

## 그림 · 영상

찍은 증거를 모두 적는다. 파일은 이 문서와 같은 폴더나 프로젝트가 정한 증거 폴더(일 이름으로 나눔)에 둔다.

**파일이 실제로 있어야 한다.** 보기와 느낌 · UI 일의 증거는 기본으로 일을 막는다. 여기에 이름만 있고 옆에 파일이 없으면 그 기준은 채워지지 않는다.

| 1 | <파일 이름> | <보이는 것 짧게> | <번호> | <식별 · 시각> |
| 2 | <파일 이름> | | <번호> | |

## 검토

보기와 느낌 일은 아래 검토 판정이 있어야 끝났다고 한다 — 그 기능을 맡은 기획 역할이나 아트 디렉터, 또는 처음 보는 검토 역할. UI 일은 바뀐 화면마다 남긴 그림으로 닫고, 검토는 있으면 좋지만 꼭 있어야 하지는 않다.
작은 프로젝트면 검토 역할 하나가 겸해도 된다. 뜻은 끝났다고 하기 전에 누군가 일부러 증거를 읽었다는 것이다.

| 검토한 역할 | 본 것 | 판정(통과 · 실패 · 못 봄 · 해당 없음) | 근거 | 날짜 |
|---|---|---|---|---|
| <예: 아트 디렉터 · 그 기능의 기획 역할> | <읽은 증거> | <판정> | <한 줄> | <날짜> |

사람이 정한 것: <보기와 느낌이 의도에 맞는지 사람이 정했으면 누가 · 언제 · 무엇 — 없으면 「없음」>

더 받고 싶은 검토(예: 구현 역할 · QA 리드)가 있으면 줄을 더한다. 줄마다 꼭 받아야 하는 검토로 읽으니 실제로 볼 역할만 넣는다.

검토할 역할을 당장 못 구하면 판정을 「못 봄 — 이유」로 둔다. 못 봄인 검토는 그 일을 끝났다고 하기 전에 푼다.

이 문서는 일 카드 옆이나 프로젝트가 정한 증거 폴더에 일 이름으로 둔다.
