> **쓰는 법** — 누가 채우나: 접근성 전문가(`accessibility-specialist`) · 없으면 UX 디자이너(`ux-designer`)가 겸하고 겸했다고 적는다 · 시험은 QA 테스터(`qa-tester`)와 나눈다 · 언제: 기술 준비 단계에 한 번 만들고, 단계 점검 뒤 · 접근성 점검 뒤 · 시스템 목록에 새 시스템이 들어올 때 고친다 · 줄여도 되는 절: 목표 단계보다 높은 기능 줄은 「해당 없음」으로 두고, 모바일 · 특정 콘솔이 범위 밖이면 그 플랫폼 줄을 「해당 없음」과 이유로 · 사람이 정할 것: 목표 단계 · 일부러 하지 않는 것 · 자막 기본값 · 사용자 시험과 바깥 자문 · 점검 의뢰(돈이 든다) — 게임 내용과 돈. 절을 채울 때는 「접근성 요구 길잡이」(`templates/accessibility-requirements-guide`)에서 같은 이름의 절만 읽는다. 채운 문서에서는 이 칸을 지운다.
>
> 총괄은 이 글과 함께 `templates/accessibility-requirements-guide`를 꺼낸다. `gaf library take <칸>/<id>…`로 꺼낸 프로젝트 문서 경로(기본 `docs/서랍/<칸>/<id>.md`)를 맡기는 글에 적는다.

| 검토 | <검토한 역할 · 판정(통과 · 실패 · 못 봄 · 해당 없음) · 근거> |
| 사람이 정한 것 | <누가 · 언제 · 무엇 — 목표 단계와 약속을 고친 기록> |

외부 기준의 이름을 적는 것은 충족한다는 뜻이 아니다. 최신 요구는 그 기준과 플랫폼의 공식 문서로 확인하고, 이 문서만으로 기준 충족이나 인증을 말하지 않는다.

**왜 있나**: 화면마다의 접근성 메모는 화면 명세에 쓴다. 이 문서는 프로젝트 전체의 접근성 약속 · 모든 시스템을 가로지르는 기능표 · 시험 계획 · 점검 기록을 담는다. 기능이 여기 약속과 부딪히면 이 문서가 이긴다 — 약속이 아니라 기능을 바꾼다. 약속을 바꾸려면 사람이 정하고 위 「사람이 정한 것」에 남긴다.

## 목표 단계 정의

### 단계

| 단계 | 핵심 약속 | 드는 품 |
|---|---|---|
| **기본** | 플레이어가 보는 중요한 글이 표준 해상도에서 읽힌다. 색 구분만 요구하는 기능이 없다. 음악 · 효과음 · 음성 음량을 따로 조절한다. 빛 민감 위험 없이 끝까지 할 수 있다 | 낮음 — 주로 설계 제약 |
| **표준** | 기본 + 모든 플랫폼에서 입력 다시 묶기 · 말하는 이 표시가 있는 자막 · 글자 크기 조절 · 색약 모드 하나 이상 · 늘리거나 바꿀 수 없는 시간 제한 입력 없음 | 중간 — 따로 구현할 일 |
| **포괄** | 표준 + 메뉴 화면 낭독기 · 모노 소리 · 난이도 보조 · HUD 위치 바꾸기 · 움직임 줄이기 · 플레이에 중요한 모든 소리의 화면 신호 | 높음 — 플랫폼 API 연결과 큰 UI 구조 |
| **모범** | 포괄 + 자막 전부 꾸미기(글꼴 · 크기 · 색 · 배경 · 위치) · 고대비 모드 · 인지 부담 보조 도구 · 소리만인 신호 모두에 진동 대안 · 바깥 제3자 점검 | 아주 높음 — 따로 접근성 예산과 전문가 자문 |

**확인할 질문**: 대상 플랫폼 · 시장이 요구하는 최저선은 어느 단계에 해당하나 — 공식 문서로 확인하고 확인한 날을 적는다.

### 이 프로젝트의 약속

**목표 단계**(사람이 정한다): <기본 · 표준 · 포괄 · 모범>

**이유**: <3~5문장 — 장르의 장벽 · 대상 플레이어 · 플랫폼 요구 · 팀 여력 · 한 단계 내리면 잃는 것. 길잡이의 점검 목록과 예 참고>

**단계 기준 위로 더하는 것**:
- <단계 기준보다 올린 기능 + 까닭>

**일부러 빼는 것**:
- <뺀 기능 + 까닭 — 아래 「일부러 하지 않는 것」 표에도 적는다>

### 색만으로 전하는 곳 점검

색이 유일한 구분인 플레이 · UI 요소를 모두 적고 출시 전에 푼다. 푼 줄에는 색 아닌 보조가 있고, 프로젝트가 선택한 색약 모드에서도 통한다. 표준 이상은 색약 모드를 하나 이상 고른다. 기능표에서 고르지 않은 모드는 「해당 없음 — 다른 모드로 목표 충족」과 고른 모드를 적는다.

## 운동 접근성

| 기능 | 목표 단계 | 범위 | 상태 | 구현 메모 |
|---|---|---|---|---|
| 입력 다시 묶기 | 표준 | 모든 플레이 입력 · 모든 플랫폼 | 시작 전 | 기본으로 묶인 입력은 모두 다시 묶을 수 있다 · 키보드 · 마우스 · 패드 · 지원하는 주변기기마다 따로 · 두 동작을 같은 입력에 함께 묶지 않는다(부딪히면 경고) · 플레이어 프로필에 저장 |
| 입력 방식 바꾸기 | 표준 | PC | 시작 전 | 다시 시작하지 않고 언제든 키보드 · 마우스와 패드 사이를 바꾼다 · 안내의 버튼 아이콘이 지금 장치를 따른다 |
| 한 손 모드 | <단계> | <두 손이 함께 필요한 기능> | 시작 전 | 여러 입력을 함께 누르는 동작을 모두 점검한다 · 한 손으로 안 되면 켜고 끄기나 누르고 있기를 켜고 끄기로 바꾼 길을 준다 · 한 손 길이 있는 것과 없는 것을 적는다 |
| 누르고 있기 대안 | 표준 | 모든 누르고 있기 입력 | 시작 전 | 「[버튼]을 누르고 있어 [동작]」마다 켜고 끄기 대안 · 첫 누름에 켜지고 둘째에 꺼진다 · 예: 누르고 있어 달리기 → 달리기 켜고 끄기 · 게임의 누르고 있기 입력을 모두 적는다 |
| 빠른 연타 대안 | 표준 | 연타 · 빠른 입력 이어짐 | 시작 전 | 초당 <프로젝트 값>번 넘게 이어 누르는 입력에는 한 번 누르는 켜고 끄기 대안 |
| 입력 시간 조절 | 표준 | 짧은 반응 입력 · 시간 맞춤 누르기 · 리듬 입력 | 시작 전 | 접근성 설정에 시간 창 배율 · 범위 <프로젝트 값> · 기본 1배 · 시간 맞춤 입력을 모두 적고 모든 배율에서 시험 |
| 조준 보조 | 표준 | 원거리 전투 · 겨냥 | 시작 전 | 켜고 끔만이 아니라 세기 · 반경 · 끌림(대상에 붙음) · 느려짐(대상 근처 감속)을 따로 · 기본값은 거슬리지 않고 돕는 느낌으로 조절 |
| 자동 달리기 · 이동 보조 | 표준 | 이동 | 시작 전 | 달리기 켜고 끄기(위) · 자동 달리기(방향을 정하면 입력 없이 계속) · 보통 플레이에서 계속 누르고 있는 이동 입력을 적는다 |
| 발판 · 이동 보조 | <단계> | <발판 넘기가 있으면> | 시작 전 | 너그러운 모서리 잡기 · 떨어진 뒤 잠깐 뛸 수 있는 시간 늘리기 · 점프 높이 조절이 이 게임 설계에 맞는지 본다 · 발판 넘기가 없으면 해당 없음 |
| HUD 위치 바꾸기 | 포괄 | 모든 HUD 부품 | 시작 전 | 체력 · 미니맵 · 퀘스트 추적을 원하는 곳으로 · 머리 추적이나 시선 장치를 써 주변 시야가 좁은 플레이어에게 특히 중요 |
