> **쓰는 법** — 누가 채우나: 릴리스 매니저(상점 자료 · 빌드 준비) · QA 테스터(새 계정에서 설치해 본 결과) · 언제: Steam 출시가 정해진 뒤, 출시 점검표(`templates/release-checklist-template`) · 출시 준비표(`templates/launch-checklist`)의 인증 칸에 옮겨 붙인다 · 줄여도 되는 절: SDK · 업적 · 클라우드 저장 · Steam Deck은 이 게임이 쓰기로 했을 때만 본다 — 아니면 「해당 없음(이유)」, 아직 정하지 않았으면 「못 봄 — 아직 안 정함」 · 사람이 정할 것: 빌드 올리기 · 페이지 공개 · 출시(배포 · 게시 — 되돌리기 어려운 일) · 가격 · 출시일(돈).
>
> 총괄은 이 글과 함께 `templates/release-checklist-template`를 꺼낸다. 정식 출시에서는 `templates/launch-checklist`도 꺼내며, 프로젝트 문서 경로를 맡기는 글에 적는다.
>
> Steam의 요구와 심사 규칙은 바뀐다. 줄마다 「최신 공식 요구를 확인했나(언제 · 어디서)」를 적고, 이 표를 심사 통과 기준으로 쓰지 않는다. 채운 문서에서는 이 칸을 지운다.

# 인증 — Steam

| 항목 | 이 게임에 해당하나 | 최신 공식 요구를 확인했나(언제 · 어디서) | 판정 | 근거 · 이유 |
|---|---|---|---|---|
| Steamworks SDK를 넣고 시험했다 | | | | |
| 상점 페이지 완성 — 캡슐 그림 · 트레일러 · 설명 · 시스템 요구 | | | | |
| 디포 빌드가 올라가 있고 새 계정에서 깨끗이 설치된다(올리기는 사람이 정한 뒤) | | | | |
| 업적이 동작한다 | | | | |
| 클라우드 저장이 동작한다 | | | | |
| Steam Deck 호환을 확인했다(대상일 때) | | | | |
| Steam의 공통 내용 규칙을 읽었다(읽은 판 · 날짜) | | | | |

「이 게임에 해당하나」 칸: 해당 · 해당 없음(이유) · 아직 안 정함. 판정 칸: 통과 · 실패 · 못 봄 · 해당 없음(이유). 아직 정하지 않은 것은 「못 봄 — 아직 안 정함」으로 적는다.
