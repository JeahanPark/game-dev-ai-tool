> **쓰는 법** — 누가 채우나: 릴리스 매니저(요구 문서 확인 · 제출 자료 준비) · QA 테스터(기기에서 해 본 결과) · 언제: 콘솔 출시가 정해진 뒤, 출시 점검표(`templates/release-checklist-template`) · 출시 준비표(`templates/launch-checklist`)의 인증 칸에 옮겨 붙인다 · 줄여도 되는 절: 이 게임에 없는 기능의 줄(예: 업적 · 트로피가 없음)은 「해당 없음(이유)」으로 둔다 · 사람이 정할 것: 어느 콘솔에 낼지(돈 · 계약) · 인증 제출(되돌리기 어려운 일 — 역할은 준비까지만).
>
> 총괄은 이 글과 함께 `templates/release-checklist-template`를 꺼낸다. 정식 출시에서는 `templates/launch-checklist`도 꺼내며, 프로젝트 문서 경로를 맡기는 글에 적는다.
>
> 콘솔의 인증 요구(TRC · TCR · Lotcheck 등)는 개발자 계약 아래 받는 비공개 문서일 수 있고 판마다 바뀐다. 이 표의 줄은 확인할 질문일 뿐 인증 기준이 아니다 — 이 표를 다 채워도 인증 통과가 아니다. 줄마다 「최신 공식 요구를 확인했나(언제 · 어디서)」를 적고, 확인 못 했으면 판정은 못 봄이다. 모든 줄을 모든 콘솔의 필수로 단정하지 않는다. 채운 문서에서는 이 칸을 지운다.

## 점검
| 항목 | 이 게임에 해당하나 | 최신 공식 요구를 확인했나(언제 · 어디서) | 판정 | 근거 · 이유 |
|---|---|---|---|---|
| 요구 문서(TRC · TCR · Lotcheck 등)의 점검 목록을 다 돌았다 | | | | |
| 플랫폼 보유자에게 낼 인증 제출 자료를 준비했다(제출은 사람이 정한다) | | | | |
| 플랫폼 업적 · 트로피 연동을 시험했다 | | | | |
| 보호자 통제 설정을 따른다 | | | | |
| 저장 데이터 규칙 — 손상 · 저장 공간 가득 · 사용자 바꾸기 | | | | |
| 컨트롤러 배치 규칙 · 플랫폼에 맞는 버튼 안내 | | | | |
| 일시 중지 · 복귀를 확인했다 | | | | |
| 연령 등급을 받았다 — 필요한 기관(예: ESRB · PEGI · 지역 등급)은 공식 요구로 확인 | | | | |

「이 게임에 해당하나」 칸: 해당 · 해당 없음(이유) · 아직 안 정함. 판정 칸: 통과 · 실패 · 못 봄 · 해당 없음(이유). 아직 정하지 않은 것은 「못 봄 — 아직 안 정함」으로 적는다.
