# 상호작용 패턴 길잡이 이동과 피드백

시간 · 버튼 이름은 모두 예이고, 이 게임 값은 틀의 「애니메이션 기준」 표와 <프로젝트 값>에서 정한다. 엔진 구현은 프로젝트의 엔진 참조 문서와 그 엔진 전문가 역할이 정한다.

## 이동 패턴

#### 화면 쌓기 · 빼기 · 바꾸기

화면이 이동 쌓임에 들어오고 나가는 세 방식이다.

| 패턴 | 계기 | 애니메이션 | 쌓임 동작 | 초점 동작 |
|---|---|---|---|---|
| 쌓기 | 더 깊이 들어감(아래 메뉴 · 상세 보기 열기) | 새 화면이 오른쪽에서 들어오고 앞 화면은 왼쪽으로 밀리며 어두워진다 | 앞 화면은 쌓임에 남는다 | 새 화면의 첫 누르는 부품으로 |
| 빼기(뒤로) | 뒤로 버튼 · 입력 장치의 취소 입력(아래 「취소 · 뒤로」) | 지금 화면이 오른쪽으로 나가고 앞 화면이 왼쪽에서 들어오며 밝아진다 | 지금 화면이 쌓임에서 빠진다 | 쌓기를 일으킨 부품으로 돌아간다 |
| 바꾸기 | 같은 급의 화면으로(아래도 위도 아님) · 불러오기 화면 | 지금 화면이 사라지고 새 화면이 나타난다 · 방향 없음 | 지금 화면이 빠지고 새 화면이 들어간다 | 새 화면의 첫 누르는 부품으로 |

**애니메이션 길이**: 쌓기 · 빼기 <프로젝트 값>(원문 예: 250ms ease-in-out) · 바꾸기 사라짐 + 나타남 <프로젝트 값>.

**움직임 줄이기**: 미끄러짐은 모두 페이드로 바뀌고 길이가 짧아진다(<프로젝트 값>).

**구현 때 볼 것**: 화면 쌓임을 한 곳이 관리한다(쌓기 · 빼기 · 바꾸기 — 바꾸기는 빼기 뒤 쌓기를 중간 쌓임 상태 없이). 화면마다 입력을 따로 받게 나눈다. 쌓기 전에 「돌아갈 초점」 부품을 기억해 두고 빼기 때 되돌린다.

#### 초점 관리

초점 관리는 게임 UI에서 가장 흔한 키보드 · 패드 접근성 실패다. 아래 규칙을 모든 화면에서 같게 지킨다. 플레이어가 어느 부품에 초점이 있는지 못 보거나, Tab · 방향 버튼을 눌러도 보이는 결과가 없는 상태가 있어서는 안 된다.

| 규칙 | 설명 |
|---|---|
| 화면 열림 | 가장 그럴듯한 누르는 부품에 초점 — 보통 주 버튼 · 첫 목록 줄, 또는 전에 왔던 화면이면 마지막에 초점이 있던 부품. 누를 수 없는 부품에는 두지 않는다 |
| 화면 닫힘 · 빼기 | 이동을 일으킨 부품(화면을 연 버튼 · 고른 목록 줄)으로 돌아간다. 그 부품이 없어졌으면 바로 앞의 누르는 부품으로 |
| 모달 열림 | 초점이 모달 안에 갇힌다 — 모달 대화상자 패턴 참고 |
| 모달 닫힘 | 모달을 연 부품으로 돌아간다 |
| 부품을 못 쓰게 됨 | 초점이 있던 부품이 못 쓰게 되면 Tab 차례의 다음 쓸 수 있는 부품으로 |
| 부품이 사라짐 | 초점이 있던 부품이 장면에서 빠지면 Tab 차례의 바로 앞 부품으로 |
| 누르는 부품이 없는 화면 | 초점 관리는 할 일이 없다. 뒤로 · 취소 입력은 여전히 된다 |
| Tab 키(키보드) | 문서 차례(왼쪽 → 오른쪽, 위 → 아래)로 앞으로 · Shift+Tab은 뒤로 |
| 방향 버튼(패드) | 누른 방향의 공간으로 옮긴다. 패드에서는 엄격한 Tab 차례보다 공간 이동이 낫다. 서로 상관없는 구역 사이로 초점이 돌지 않게 한다(예: 탭 줄과 내용은 따로 이동 구역) |
| 초점은 늘 보인다 | 키보드 · 패드로 초점이 오면 초점 테두리나 같은 표시가 늘 보여야 한다. 초점 표시를 끄지 않는다 |

#### 취소 · 뒤로

「뒤로」는 모든 메뉴에서 가장 많이 쓰는 이동 입력이다. 예외 없이 모든 화면에서 같게 한다.

| 입력 장치 · 플랫폼 | 입력 | 동작 |
|---|---|---|
| 키보드 | 예: Esc | 맨 위 모달을 닫는다 → 없으면 쌓임에서 한 화면 뒤로 → 뿌리 화면(메인 메뉴)이면 「끝낼까?」 확인을 연다 |
| PC의 게임 패드 | <그 패드 배치의 취소 버튼 — 예: Xbox 배치의 B · PlayStation 배치의 원> | 키보드와 같다 |
| 콘솔 | <그 플랫폼의 취소 버튼> | 키보드와 같다. 확인 · 취소 버튼의 관례는 플랫폼마다 다를 수 있다(원문은 한 플랫폼의 일부 게임이 반대로 쓴다고 짚었다) — 대상 플랫폼의 공식 문서로 확인하고 결정을 적는다 |

**규칙**: 이 입력을 「뒤로 · 취소」 말고 다른 동작에 쓰지 않는다. 뒤로 갈 수 없는 화면(예: 게임이 멈추고 플레이어가 꼭 골라야 할 때)에서는 아무 일도 하지 않거나 「골라야 한다」를 알리고, 화면을 떠나지 않는다. 화면마다 취소 동작을 화면 명세에 분명히 적는다.

## 피드백과 불러오기 패턴

#### 불러오는 상태

| 범위 | 패턴 | 메모 |
|---|---|---|
| 전체 화면(처음 불러오기) | 게임 그림 · 진행 막대(되도록 끝이 있는 것) · 팁 글(선택)이 있는 불러오기 화면 | 빈 검은 화면을 쓰지 않는다 — 읽거나 볼 것을 준다 |
| 전체 화면(지역 넘어가기) | 검게 사라짐 → 불러오기 화면 → 새 장면으로 밝아짐 | 앞 장면이 툭 사라지는 느낌을 페이드가 없앤다 |
| 부품 안 | 불러오는 부품 자리에 도는 표시나 모양 자리 표시 · 내용이 와도 배치가 밀리지 않는다 | 배치가 많은 내용은 도는 표시보다 내용 모양을 흉내 낸 회색 자리 표시가 낫다 — 들어올 때 배치 밀림을 막는다 |
| 뒤에서 도는 일 | <프로젝트 값>초를 넘을 때까지 표시 없음 · 넘으면 작은 도는 표시나 알림 | 금방 끝나는 일에 표시를 띄우면 깜박임이 기다림보다 더 거슬린다 |

**접근성**: 불러오기 시작 때 낭독기가 「<맥락> 불러오는 중, 기다려 달라」, 끝나면 「<맥락> 다 불러왔다」를 읽는다. 전체 화면 불러오기는 그 화면도 낭독기로 읽혀야 한다 — 팁 글과 UI를 넘긴다.

#### 빈 상태

빈 상태는 게임 UI에서 가장 덜 설계되는 곳이다. 「여기에 아이템을 모으는구나」와 「왜 아무것도 없지? 고장인가?」의 차이를 만든다. 빈 목록과 격자마다 설계한 빈 상태가 있어야 한다. 빈 상태는 오류가 아니라 시작점이다.

| 위치 | 빈 상태 내용 | 메모 |
|---|---|---|
| 인벤토리(아이템 없음) | 아이콘(은은하게 · 크게 · 가운데) · 「가방이 비었다.」 · 덧붙임 「여정에서 찾은 아이템이 여기에 모인다.」 | 「찾은 아이템이 없다」라 하지 않는다 — 「찾은」은 검색 실패로 읽힌다 |
| 퀘스트 기록(진행 중 퀘스트 없음) | 아이콘 · 「진행 중인 퀘스트가 없다.」 · 덧붙임 「<퀘스트 표시>가 있는 인물과 이야기해 퀘스트를 시작한다.」 | 분명한 할 일을 준다 |
| 업적(받은 것 없음) | 아이콘 · 「아직 업적이 없다.」 · 힌트 업적 목록 「<동작>을 해 첫 업적을 받아 보자.」 | 빈 것이 아니라 동기를 준다 |
| 검색 결과(맞는 것 없음) | 아이콘 · 「'<검색어>'에 맞는 것이 없다.」 · 덧붙임 「다른 말로 찾거나 [모두 보기].」 | 검색어를 되비추고 다른 길을 준다 |

**규칙**: 빈 상태마다 아이콘 · 글, 그리고 덧붙임 글이나 동작 버튼 가운데 하나가 있다. 설명 없는 빈 칸은 쓰지 않는다.

#### 오류 상태

| 오류 종류 | 패턴 | 말투 |
|---|---|---|
| 입력 검사(입력칸) | 칸 아래 그 자리 오류 글 · 글 왼쪽 오류 아이콘 · 칸 테두리를 오류 색으로(아이콘이 있어 색약에도 안전) | 차분하고 구체적으로 — 예: 「이름은 <프로젝트 값>~<프로젝트 값>자여야 한다.」 「잘못된 입력」이 아니다 |
| 동작 실패(저장 · 연결 오류) | 가벼운 실패는 알림 · 큰 실패(세이브 파일을 쓸 수 없음)는 모달 대화상자 | 차분하고 할 일이 있게 — 「저장하지 못했다. 저장 공간을 확인해 달라.」 「치명적 오류」가 아니다 |
| 시스템 오류(멈춤 · 데이터 손상) | 전체 화면 오류 · 오류 번호 · 되살리기 보기(「게임 다시 시작」 · 「마지막 세이브 불러오기」) · 지원 연락처 | 안심시키게 — 문제를 인정하고 플레이어가 고를 길을 준다. 플레이어를 탓하지 않는다 |
| 가벼운 오류(지금 못 하는 동작) | 알림이나 그 자리 글 | 까닭을 말한다 — 「골드가 모자라다」. 「사용할 수 없음」이 아니다 |

**원칙**: 오류 글은 플레이어 탓을 하지 않는다. 게임이 무슨 일이 있었고 다음에 무엇을 하면 되는지 알려 주는 글이다. 오류 글에서 「잘못된」 같은 말을 빼고 구체적인 설명으로 바꾼다.
