>
> - 총괄은 「추천 설계 차례」로 일의 차례를 정해 맡긴다. 같은 층에서 서로 기대지 않는 시스템은 동시에 맡길 수 있다.
> - 바탕 문서에 없는데 역할이 짐작해 넣은 시스템은 이름 뒤에 「(추측)」을 붙인다.
> - 갈래 · 우선순위의 이름은 프로젝트가 정한 구분을 쓴다. 층은 프로젝트가 정한 한 벌(예: 바탕 · 핵심 · 기능 · 표현 · 다듬기)을 쓴다.

## 갈래
| 갈래 | 설명 | 흔한 시스템 |
|---|---|---|
| 핵심 | 모든 것이 기대는 바탕 | 플레이어 조종 · 입력 · 물리 · 카메라 · 장면 관리 · 상태 기계 |
| 게임플레이 | 게임을 재미있게 하는 것 | 전투 · AI · 잠입 · 이동 능력 · 상호작용 |
| 성장 | 플레이어가 자라는 방식 | 경험치 · 단계 · 능력 나무 · 열리는 것 · 업적 · 평판 |
| 경제 | 자원이 생기고 쓰이는 것 | 화폐 · 전리품 · 제작 · 상점 · 아이템 자료 · 떨어지는 표 |
| 저장 | 상태를 남기고 잇는 것 | 저장 · 불러오기 · 설정 · 클라우드 맞춤 · 프로필 |
| UI | 플레이어가 보는 정보 | HUD · 메뉴 · 인벤토리 화면 · 대화 화면 · 지도 · 알림 |
| 소리 | 소리와 음악 | 음악 관리 · 효과음 · 배경 소리 · 상황 따라 바뀌는 음악 · 목소리 |
| 서사 | 이야기와 대화 전달 | 대화 · 임무 추적 · 컷신 · 일지 · 설정 글 |
| 바깥 | 핵심 루프 밖의 시스템 | 분석 · 입문 안내 · 접근성 설정 · 사진 모드 |

<모든 게임에 모든 갈래가 필요하지는 않다. 맞지 않는 갈래는 지우고, 필요하면 갈래를 더한다.>

## 추천 설계 차례
<의존 차례와 우선순위를 합친 차례. 이 차례로 설계한다. 시스템마다 기획서를 끝내고 검토한 뒤 다음으로 가지만, 같은 층에서 서로 기대지 않는 시스템은 동시에 설계해도 된다. 총괄이 이 표로 일을 나눠 맡긴다.>

| 2 | <둘째> | 최소판 | 바탕 | <…> | <…> |
