> **쓰는 법** — 누가 채우나: 릴리스 매니저(합치기) · 절마다 그 영역의 역할(예: 코드는 리드 프로그래머 · QA는 QA 리드 · 상점과 커뮤니티는 커뮤니티 매니저 · 서버는 데브옵스 엔지니어) · 언제: 정식 출시를 앞두고, 또는 연습으로 · 줄여도 되는 절: 서버 · 분석 · 멀티플레이 · 업적 · 결제 · 홍보처럼 이 게임에 없는 것은 줄을 지우지 말고 「해당 없음(이유)」 · 사람이 정할 것: 출시일 · 출시 · 배포 · 상점 제출 · 공지 게시 · 키 배포(되돌리기 어려운 일) · 서버 · 법률 검토 · 홍보처럼 돈이 드는 일 · 받아들일 위험.
>
> 총괄은 이 글과 함께 `templates/release-checklist-template`를 꺼내 같은 출시 후보의 결과를 옮기게 한다.
>
> 총괄은 이 글과 함께 `templates/release-platform-requirements`와 대상 상점마다 필요한 인증 블록(`templates/certification-console` · `templates/certification-steam` · `templates/certification-itch` · `templates/certification-none`, 대상 미정이면 `templates/certification-unknown`)을 꺼낸다. `gaf library take <칸>/<id>…`로 꺼낸 프로젝트 문서 경로(기본 `docs/서랍/<칸>/<id>.md`)를 맡기는 글에 적는다.
>
> 정식 출시는 출시 준비표(`templates/launch-checklist`) · 판마다는 출시 점검표(`templates/release-checklist-template`) — 겹치는 줄은 출시 점검표의 결과를 옮긴다.
>
> 판정 칸: 통과 · 실패 · 못 봄 · 해당 없음. 아직 정하지 않은 조건은 「못 봄 — 아직 안 정함」으로 적는다. 근거 칸에는 증거나 사람의 답(누가 · 언제)을 적고, 해당 없음에는 이유를 적는다. 사람만 아는 항목(당번 · 약관 · 가격)은 총괄이 영역마다 묶어 한 번에 묻고, 답이 없으면 못 봄으로 둔다.
>
> 저장 암호화 · 서버 · 분석 · 업적 · 전 직군 서명은 모든 게임의 의무가 아니다. 상점 · 콘솔의 인증 요구는 「최신 공식 요구를 확인했나(언제 · 어디서)」 칸으로만 남기고, 이 표를 인증 기준으로 쓰지 않는다. 채운 문서에서는 이 칸을 지운다.

## 출시 판정

**전체 상태**: <통과 · 실패 · 못 봄 · 해당 없음> — 조건이 있으면 통과 + 조건 목록

먼저 맞는 것이 이긴다: 항목 · 절에 실패가 하나라도 있으면 **실패** · 실패가 없고 못 봄(「못 봄 — 아직 안 정함」 포함)이 하나라도 있으면 **못 봄**(하나하나 이름을 적는다) · 아니면 **통과**. 기록된 우회 방법을 확인했거나 사람이 위험을 받아들여 진행하기로 정한 항목은 「통과 + 조건 목록」으로 적는다. 그 밖의 실패는 실패로 남긴다. 조건 목록은 합칠 때도 남긴다. 근거 없이 빈 항목은 못 봄이다. 합치는 순서는 `rules/verdicts`를 따른다.

이 판정은 출시 결정이 아니다. 출시 · 배포 · 상점 제출 · 게시는 사람이 정한다.

### 막는 항목
<우회 방법도 받아들인 위험도 없는 실패 전부 — FIXME · 디버그 출력 · 임시 에셋 · 박힌 개발용 값 · 열린 S1 · 실패한 빌드나 시험 등>

### 조건부 항목
<기록된 우회 방법이 있거나 받아들인 위험인 부족 모두 — 예: 까닭이 기록된 HACK · 예외가 기록된 S2(프로젝트가 예외를 허용할 때). 우회 방법, 또는 위험을 받아들인 사람(누가 · 언제)을 적는다>

### 검토
| 검토한 역할 | 본 것 | 판정(통과 · 실패 · 못 봄 · 해당 없음) | 근거 |
|---|---|---|---|
| <예: 크리에이티브 디렉터> | 내용과 경험의 질 | | |
| <예: 테크니컬 디렉터> | 기술 상태와 안정성 | | |
| <예: QA 리드> | 품질과 시험 범위 | | |
| <예: 프로듀서> | 일정과 전체 준비 | | |
| <예: 릴리스 매니저> | 빌드와 배포 준비 | | |

이 출시에 걸린 역할만 넣는다. 모든 직군의 서명을 받는 표가 아니다.

사람이 정한 것: <누가 · 언제 · 무엇 — 예: 출시일 확정 · 출시함 · 미룸 · 조건부 항목의 위험을 받아들임>
